## Context

See proposal.md for motivation. Same constraints as the other three SDKs (see the equivalent `go-sdk`/`python-sdk`/`node-sdk` changes): hush-hush's `api/openapi.yaml` is spec-first, linted but not semantically drift-checked; no real API-version concept; auth is a static bearer token on write paths only, plus an optional unverified `X-Caller` header.

## Goals / Non-Goals

**Goals:**
- A deterministic, mechanically regenerable client.
- Idiomatic PHP: PSR-4 autoloading, typed properties/return types throughout, no bare associative-array payloads.
- A clear generated/hand-written boundary that survives regeneration.
- A regeneration pipeline that surfaces breaking spec changes via classification, even without gating merge.

**Non-Goals:**
- Async I/O — PHP's standard request-per-execution model makes an async client non-idiomatic for a typical PHP consumer; this SDK is synchronous only, unlike the other three languages.
- A unified cross-language docs site.
- Any change to hush-hush's server or its spec.
- Implementing Pact provider verification inside hush-hush's own CI.
- Automating the Packagist publish step — deliberately manual, tracked in hush-hush issue #76.

## Decisions

**Generator: `openapi-generator`'s PHP template**, not a hosted platform. PHP has no equivalent to `oapi-codegen`/`openapi-python-client`/`openapi-typescript`'s narrower, more idiomatic scope — `openapi-generator` is the standard free tool with PHP coverage. Hosted platforms (Speakeasy/Fern/Stainless) rejected project-wide in favor of free OSS tooling, and PHP coverage among them is inconsistent besides.

**Transport: Guzzle, via `openapi-generator`'s default "guzzle" library target — not real PSR-18.** Originally planned as a real PSR-18 `ClientInterface` so a consumer could swap in their own HTTP client. Checked against the actual generator during implementation: `openapi-generator`'s PHP target has a `library=psr-18` option, but it's explicitly marked beta, generates against `php-http/client-common`'s `PluginClient`/plugin-based async architecture (not Guzzle's `HandlerStack`), and pulls in `php-http/discovery`, `php-http/httplug`, and `php-http/message` as additional dependencies — none of which compose with this SDK's hand-written Guzzle `Middleware::retry()`-based retry layer without a rewrite of that layer too. Given the beta status and the added dependency/complexity surface, the default "guzzle" target is used instead: the generated `Api` classes accept `GuzzleHttp\ClientInterface` (Guzzle's own interface, not `Psr\Http\Client\ClientInterface`), and this SDK's hand-written `Client` constructor's HTTP-client override parameter is typed to match. A consumer can still substitute their own configured Guzzle client (e.g. with a custom handler stack), just not an arbitrary PSR-18 implementation from another library.

**Synchronous only — a deliberate deviation from "async-first."** The original generic SDK-generation prompt this project started from assumes async-first as a cross-language default, but PHP's typical execution model (one request, one process, no persistent event loop in the common case) makes a sync client the idiomatic choice; ReactPHP/Amp-based async exists in PHP but isn't what a typical integrator reaching for an HTTP API client expects.

**Generated/hand-written boundary via header comment and namespace separation.** `openapi-generator` has no custom-code region either; generated classes live under a `Generated\` namespace with `// Code generated by openapi-generator; DO NOT EDIT.` headers, and the hand-written wrapper layer lives in its own namespace, composing rather than extending generated classes. A CI check fails if a generated file's diff isn't purely mechanical regeneration output.

**Spec pinning via git submodule**, same approach as the other SDKs: the submodule's pinned commit is the version record; the hand-written client's version constant additionally states the pinned commit for human readability.

**Versioning via spec diff.** `openapi-diff` compares the current pinned commit against the one the last release was generated from and classifies the change as additive or breaking, driving the semver bump.

**Merge policy: full auto-merge for this session, scaffolding and all regeneration PRs alike** — an explicit, repeated grant from Ryan, given after being shown the risk that a breaking spec change can produce a small, green-CI-passing diff. The `openapi-diff` classification still runs and is surfaced on every PR for visibility; it doesn't gate merge.

**Auth: bearer token in the constructor with an `HUSH_HUSH_API_KEY` env var fallback (via `getenv()`); `X-Caller` as a per-call option, not client-level config.** Same reasoning as the other SDKs: the token is only required on write paths, and `X-Caller` attributes a specific call, not a client instance.

**Retry: network failures, 5xx, and 429 only; exponential backoff with jitter; honor `Retry-After`.** Never retry other 4xx.

**Errors: a typed exception hierarchy** (`HushHushException` base, `ApiException` subclass extending it) carrying status, an optional request-ID property (populated when a documented header is present, empty otherwise), and the parsed error body.

**Audit log: a plain typed query method, not an iterator.** hush-hush's `/audit-log` has no pagination parameters (checked directly against the spec) — it returns a flat array for the given filters, so `$client->auditLog->query($filters)` returns the full result set as an array rather than exposing a generator-backed `Iterator` over pages that don't exist.

**Packaging: Composer, PSR-4 autoloading**; publishing to Packagist is a manual maintainer step, not CI-automated, per hush-hush issue #76.

## Risks / Trade-offs

- [`openapi-generator`'s PHP templates are less consistently idiomatic than the narrower Go/Python/Node tools] → mitigated by keeping the hand-written wrapper layer as the primary consumer-facing surface; generated classes stay an internal implementation detail behind PSR-4 namespacing.
- [Guzzle-specific `ClientInterface`, not real PSR-18, is what the generator's stable "guzzle" target actually produces] → accepted after checking the beta `psr-18` alternative's added dependency/architecture cost against this SDK's own retry layer; see the "Transport" decision above.
- [Full auto-merge applies to all regeneration PRs, so a breaking spec change can auto-merge as a small diff] → accepted risk, per Ryan's explicit repeated auto-merge grant. `openapi-diff`'s classification remains visible after the fact even though it doesn't block.
