## Why

hush-hush issue [#79](https://github.com/alrayyes/hush-hush/issues/79) asks for an official PHP SDK, companion to the Go SDK in [#74](https://github.com/alrayyes/hush-hush/issues/74), so PHP integrators get typed methods instead of hand-rolled HTTP calls against `api/openapi.yaml`.

## What Changes

- New public repo `github.com/alrayyes/hush-hush-php` providing a typed PHP client for hush-hush's v1 API surface (create/get/update/delete, audit-log query).
- Request/response types and a base client generated from hush-hush's `api/openapi.yaml` via `openapi-generator`'s PHP template; generated files carry a `// Code generated by openapi-generator; DO NOT EDIT.` header, checked in CI.
- Hand-written wrapper layer on top of the generated client, built on a PSR-18 HTTP client (Guzzle by default, swappable per PSR-18): constructor accepting bearer token (environment-variable fallback), base URL, timeout, max retries; exponential backoff with jitter on network failures and 5xx/429 only (honoring `Retry-After`, never retrying other 4xx); typed exception hierarchy carrying HTTP status, request ID, and parsed error body; a typed audit-log query method (hush-hush's `/audit-log` has no pagination parameters, confirmed against the actual spec, so this doesn't invent an `Iterator` over one). Synchronous only — PHP's request-per-execution model makes "async-first" (from the original generic SDK prompt) non-idiomatic here; this is a deliberate deviation, not an oversight.
- The spec is pulled into the repo pinned to an exact hush-hush commit/tag (submodule or fetch step), never copy-pasted; the pinned commit is recorded in-repo.
- Versioning: semver bump decided by diffing the spec (`openapi-diff`), not by Conventional Commits on this repo.
- CI regenerates on a schedule/webhook from hush-hush's spec and opens a PR — never pushes directly. Full auto-merge applies to this repo's PRs for this session (scaffolding and regeneration alike), with the spec-diff's additive/breaking classification still surfaced on every PR for visibility even though it doesn't gate merge.
- Testing: unit tests cover only the hand-written layer (retry, auth, pagination, error mapping) against a mock PSR-18 client; contract tests run the client against a Prism mock generated from the same spec; a Pact consumer contract records real interactions for provider verification against hush-hush itself (verification step lives in hush-hush's own CI — external dependency).
- Docs: PHPDoc blocks on all public classes/methods, built into a docs site via phpDocumentor; a hand-written README quickstart covering install, auth setup, and one real call.
- Targets PHP 8.2+ (the oldest currently-supported branch as of 2026-08; 8.2 reaches EOL December 2026, tracked rather than silently baked in as permanent).
- Packaging via Composer, PSR-4 autoloading; publishing to Packagist is a deliberate manual step tracked in [#76](https://github.com/alrayyes/hush-hush/issues/76), not automated in this repo's CI.

## Capabilities

### New Capabilities

- `sdk-php`: the PHP SDK's client behavior — constructing a client, calling typed methods against hush-hush's v1 API surface, error/retry/pagination handling, and staying in sync with the pinned spec version.

### Modified Capabilities

None — this introduces a new repo and does not change hush-hush's own API behavior.

## Impact

- New repo: `github.com/alrayyes/hush-hush-php`, public, own CI/release pipeline.
- hush-hush's own README gets a link added once the SDK repo exists (an edit to that repo, made by whoever owns it).
- No changes to hush-hush's server code. Pact provider verification in hush-hush's CI is a request to that repo's owner, tracked as a dependency rather than performed here.
- Depends on hush-hush's `api/openapi.yaml` remaining the spec-first source of truth; does not modify it.
