Two real environment issues hit and fixed: (1) `pact-php`'s `guzzlehttp/psr7: ^2.4.5` constraint conflicts with `guzzlehttp/guzzle@8.1.0`'s own `^3.1` requirement — no version of pact-php (including 11.0.0-alpha2) has moved to psr7 3.x yet, so **downgraded to `guzzlehttp/guzzle@7.15.5`** (requires `psr7 ^2.13.1`, itself clean of every current psr7 security advisory, all of which affect only `<2.12.3`); (2) running `composer install` under the Alpine-based `composer:2.9.5` image and then running the tests under a separate glibc-based `php:8.5-cli` image downloads the **musl**-linked `pact.so` (the downloader's `musl()` check runs at install time, in whichever environment composer itself is running) but tries to load it under glibc, failing with a misleading `libc.so: invalid ELF header` — composer install and the actual FFI-driven test run must happen in the *same* environment. CI's `pact-consumer` job does both steps in the same `ubuntu-24.04` job for exactly this reason
