# hush-hush-php

Official PHP SDK for [hush-hush](https://github.com/alrayyes/hush-hush),
generated from its OpenAPI spec. Built from `~/.config/claude/CLAUDE.md`,
`~/.config/claude/rules/sdk-generation.md`, and this repo's own
[`openspec/`](openspec/) directory (proposal/design/specs/tasks, carried
here rather than left only in the `hush-hush-sdk` planning repo that
originated them) — read those for the "why". This file only says what's
specific to this repo.

## Gotchas

- **`src/Generated/` is generated by `openapi-generator`'s PHP template;
  never hand-edit it.** It doesn't stamp a generated-code header itself —
  `scripts/generate.sh` prepends one to every file, plus the pinned spec
  commit, which is what `codegen-drift` in CI actually checks. Only three
  supporting files, `ObjectSerializer.php`, `ApiException.php`,
  `Configuration.php`, `HeaderSelector.php`, and `Model/ModelInterface.php`
  are kept from the generator's own scaffold — every generated model
  `implements ModelInterface`, so excluding it breaks autoloading.
- **`hush-hush/` is the whole hush-hush repo, pulled in as a git
  submodule** pinned to one of its commits, only for its
  `hush-hush/api/openapi.yaml` — not this repo's own spec. Clone with
  `--recurse-submodules`. A spec change belongs in hush-hush; this repo
  picks it up on the next scheduled regeneration.
- **The generated `Api` classes accept `GuzzleHttp\ClientInterface`, not
  real PSR-18**, despite the original design intent. `openapi-generator`'s
  PHP target has a `library=psr-18` option, but it's beta, built on
  `php-http/client-common`'s plugin architecture (not Guzzle's
  `HandlerStack`), and needs extra `php-http/*` dependencies — none of
  which compose with this SDK's hand-written `RetryPolicy` without
  rewriting that layer too. See design.md's "Transport" decision.
- **`guzzlehttp/guzzle` is pinned to `7.15.5`, not the newer `8.x`.**
  `pact-foundation/pact-php` (even its 11.0.0-alpha releases) still
  requires `guzzlehttp/psr7: ^2.4.5`, which conflicts with Guzzle 8's own
  `^3.1` requirement. Guzzle 7.15.5 needs `psr7 ^2.13.1`, which is clean of
  every current psr7 security advisory (all affect only `<2.12.3`).
- **phpDocumentor is not a Composer dependency.** `./scripts/docs.sh` (run
  it on the host, since the Composer wrapper image has no Docker) runs the
  official `phpdoc/phpdoc` image with no network, pinned by tag and digest
  in `docker/phpdoc/Dockerfile`, which Dependabot's docker ecosystem
  tracks, as it does `docker/composer/`; the scripts read the pin back
  through `scripts/image.sh`.
  `phpdocumentor/phpdocumentor` requires `league/flysystem ^1`, which has
  no fix for PKSA-w9tt-7782-78jx and which `roave/security-advisories`
  refuses to install (#295). Taking it out also dropped the `league/uri`
  pins its crash needed.
- **phpDocumentor's `--ignore`/`<ignore>` exclusion doesn't work in
  3.10.0** — neither the CLI flag nor the XML config element actually
  excludes `src/Generated` from the built site. `phpdoc.dist.xml` points
  `<source>` directly at the hand-written files instead of scanning `src`
  and trying to exclude a subdirectory.
- **`config.platform.php: 8.4.99`** in `composer.json` makes Composer
  resolve as if on PHP 8.4 while the interpreter running is newer (the
  Composer image in `docker/composer/Dockerfile` bundles 8.5). It was
  added for
  `phpdocumentor/json-path`'s support ceiling; phpDocumentor is gone, so
  it may now be removable.
- **`scripts/composer.sh` passes arguments via `docker run`'s own argv
  form, not a `sh -c "composer $*"` string.** The string form silently
  re-splits and glob-expands quoted arguments (confirmed live: `--ignore
"src/Generated/*"` reached Composer as two separate positional args)
  before Composer ever sees them.
- **`AuditLogEntry::getTimestamp()` returns a `\DateTime` object, not a
  string** — openapi-generator auto-converts `format: date-time` fields.
  Format it (`->format(DATE_ATOM)` or similar) before printing or
  concatenating.
- **No TypeScript/Node/PHP GitHub-native scaffold sibling exists yet**
  (only `scaffold-go-api` does, per `skills/repo-creation/`) — every config
  file here was hand-assembled rather than cloned from a sibling.
- **npm/bun for tooling only, PHP for everything else.** `package.json`
  exists solely so commitlint/prettier/markdownlint/lefthook resolve and
  stay pinned — nothing here is JavaScript. Pinned to `bun@1.3.14`, not
  the org default of whatever's newest — `bun@1.4.0`'s default `bun.lock`
  (lockfileVersion 2) is incompatible with Dependabot's `bun` ecosystem
  support (confirmed on hush-hush-python; fixed org-wide via
  alrayyes/dotfiles#425/#426, which now pins bun below 1.4 until
  dependabot-core#15848 lands upstream).
- **Dependency audits have no ignore list.** `ci.yml`'s `audit` job runs
  `composer audit` and `bun audit` through
  [advisory-scan](https://github.com/alrayyes/advisory-scan) on the pull
  request and its base, and fails only on advisories the pull request adds.
  It runs when `composer.json`, `composer.lock`, `package.json` or `bun.lock`
  change. `advisory-scan.yml` audits `main` daily, on lock file pushes and on
  demand, and keeps one open issue titled "Dependency advisories". An
  advisory with no fix stays there until one ships.
- **`HUSH_HUSH_STAGING_URL`/`HUSH_HUSH_STAGING_API_KEY` secrets aren't set
  yet.** `e2e.yml`'s smoke tests skip cleanly until a maintainer adds them —
  Actions secrets can't be read or set by anyone but the repo owner.
- **No `actions/attest-build-provenance` in `release.yml`, despite
  `rules/releases.md` asking for it unconditionally on every GitHub repo.**
  `release.yml` only runs `release-please-action` — tags and a changelog
  entry, no build step. Packagist installs straight from the tagged git
  commit; there's no artifact (`subject-path`) for the action to attest.
  Revisit if a release job ever starts producing one.
- **`ci.yml` publishes the API reference and the test and coverage reports as
  one Pages site**, per `rules/published-reports.md`. The `test` job writes the
  reports on every run and uploads them as the `reports` artifact. `build` needs
  every other job, downloads that into `site/reports/`, builds the phpDocumentor
  reference into `site/` through `scripts/docs.sh` and stages the site. It runs
  on pull requests too, so a broken step fails before the merge. `pages-deploy`
  runs on a push to `main` only (the `github-pages` environment admits nothing
  else) and then fetches the live `coverage.xml`. A deploy replaces the whole
  site, which is why the reports are rebuilt on every push to `main` whatever
  changed. The contract, pact and mutation runs aren't in them.
